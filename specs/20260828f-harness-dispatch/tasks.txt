T1: create scripts/dispatch/dispatcher.py with the intent parser. Define a module-level constant holding the supported verbs as a literal table — exactly one entry in v1, the verb `fix` — and a function `parse_intent(text)` that takes a chat message and returns either a mapping with the keys `verb`, `repo`, `spec` and `strategy`, or None. It recognises a message whose words are, in order: a mention token beginning with `@`, then the verb, then a repo name, then a spec name; extra surrounding whitespace is not significant. `strategy` is always the literal `build-converge` in v1 and is never taken from the message — a second dimension of user input doubles the validation surface for no current need. Any message that does not match, including one with an unrecognised verb, too few words, or an empty string, returns None; it must NEVER raise, because a malformed chat message must not crash a listener. Do not import any HTTP, Kubernetes or model client in this file, and do not read the filesystem in this function. Create only this file.

T2: add the event ledger to scripts/dispatch/dispatcher.py. Define `already_seen(ledger_path, event_id)` returning True when that id has been actioned before, and `record_seen(ledger_path, event_id)` appending it. The ledger is a plain text file, one id per line. A missing ledger file is NOT an error — a fresh dispatcher has actioned nothing, so `already_seen` returns False and `record_seen` creates the file, creating any missing parent directory. Both functions must tolerate an unreadable or unwritable path without raising: losing the ledger degrades dedupe, and a dispatcher that crashes on a full disk is worse than one that occasionally repeats. This is deliberately separate from the Matrix sync cursor: the cursor may be lost on restart, and the ledger is what makes a replayed event harmless, so do not combine them.

T3: add the Job renderer to scripts/dispatch/dispatcher.py. Define `render_job(intent, *, image, namespace, run_id)` returning a Kubernetes Job object as a plain Python dict — do not emit YAML text, and do not import a Kubernetes client. `apiVersion` is `batch/v1` and `kind` is `Job`. The object must set, every time and not conditionally: the given namespace; a name derived from the run id; `spec.activeDeadlineSeconds` and `spec.ttlSecondsAfterFinished` to positive integers taken from module-level constants; `spec.backoffLimit` of 0, because the loop owns retries and a Kubernetes retry would start a second loop over the same spec; a pod `nodeSelector` of exactly `{"harness-fleet": "true"}`; the container image set from the `image` argument; and container env entries carrying the intent's repo, spec and strategy under the names REPO, SPEC and STRATEGY. Every one of those bounds exists because loop Jobs share the cluster with DNS and media, so none of them may be omitted or made optional.

T4: add the launcher and the wiring to scripts/dispatch/dispatcher.py. Define `launch(job, *, runner=None)` which serialises the Job dict to JSON and applies it by running an external command, reading the command name from the environment variable `HARNESS_KUBECTL` and defaulting to the literal `kubectl`; pass the JSON on the command's standard input with arguments `apply -f -`. Return the command's exit status. It must not raise when the command is missing — report the failure and return non-zero. Then define `handle_event(text, event_id, *, ledger_path, image, namespace)` which performs the whole flow in order: parse the intent; if there is none, return without launching anything; if the event id is already in the ledger, return without launching anything; otherwise render the Job, launch it, record the event id, and return a small result mapping saying what happened. The order is load-bearing — a message that does not parse must never reach the launcher, and an event already actioned must never launch a second time. Do not add retry logic, do not call a verify script, and do not import any model client: every judgment belongs to the worker, and this file must stay small enough to read in one sitting.

T5: write scripts/dispatch/README.md describing the contract this module implements, in prose a reader can check the code against. Cover: the single supported verb and what an unrecognised message does; why dedupe is keyed on the event id rather than the sync cursor; each bound the rendered Job always carries and the reason each exists; the two environment variables that select the apply command and the worker image; and the rule that the dispatcher validates, maps, launches and records, with every judgment living in the worker. State plainly that the module deliberately contains no model call, no gate invocation and no retry loop, and that the HTTP read API is a separate future surface. Do not restate the whole spec — this is the contract as a maintainer would need it, not a copy.

T6: set the pod restart policy in the rendered Job, in scripts/dispatch/dispatcher.py. The Job's pod template spec must set `restartPolicy` to the string `Never`. A Kubernetes Job requires it to be Never or OnFailure — without it the API server rejects the Job and it never runs at all. Never rather than OnFailure because the rendered Job already sets backoffLimit to 0: the loop owns its retries, and letting Kubernetes restart the pod would start a second loop over the same spec.
