T2: make a failed launch say why, in scripts/dispatch/dispatcher.py. launch() runs `kubectl apply -f -`, captures stderr into a PIPE, discards it, returns proc.returncode, and returns 1 from a bare `except Exception`. So "kubectl is not on PATH" and "the API server rejected this Job" are the same integer with no text attached, and in a Deployment that integer is the entire diagnostic surface a human gets at 2am. Emit the captured stderr on failure, and make the missing-runner case distinguishable from the rejected-apply case in what is emitted — an exception carrying the runner name it could not execute is not the same message as an API server's complaint about the Job body. Write to stderr, not stdout: stdout is where a caller may be reading structured output. Keep every property the current signature has: launch() must still NEVER raise, must still return an int, must still honour the `runner=` keyword and the HARNESS_KUBECTL environment override in that precedence order, and must still return 0 on success. 20260828f and 20260829a T05 both assert on launch() through that signature, so a change to its shape is a change to two other specs' gates. Emit NOTHING on success — a dispatcher that logs on the happy path buries the one line that matters. Do not add a logging dependency; this module is stdlib-only and the image is built on that assumption.
