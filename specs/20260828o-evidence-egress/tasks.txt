T1: add the artifact push helper to scripts/ralph-log.sh and wire it into the four writers that already produce artifacts. Define one helper taking the task label, the attempt number, a kind, and the path of the file just written; it POSTs that file's bytes to `{base}/runs/{run_key}/attempts/{task}/{attempt}/artifacts/{kind}`, where `{task}` is the SHORT label produced by the existing `log_task` helper — `T1`, not the task's prose, which is what `log_task` already reduces `T1: make a.` to for the artifact's own filename. Reuse that helper rather than re-deriving the slug, so an artifact's URL and its filename always name the same task; the full task text already travels in the status record and has no business in a URL. using the SAME configuration the status channel uses — `HARNESS_REPORT_URL` for the base, `HARNESS_REPORT_TOKEN` as a bearer header — and reusing the transport helper `scripts/ralph-status.sh` already provides rather than writing a second one. Two posting paths would drift, and the second one is always the one that leaks the token or blocks. Derive the run key the same way, from the identity the loop already has; do not mint a second one. Call it from `log_prompt`, `log_gate`, `log_failure`, `log_patch` and `log_meta`, each with its own kind — `prompt`, `gate`, `diff`, `patch`, `meta`. `patch` and `diff` are separate kinds because they are separate artifacts written on opposite outcomes: `log_patch` runs when an attempt PASSES and holds the change that was kept, `log_failure` runs when one FAILS and holds the verify output plus the work about to be discarded. Most tasks pass, so omitting `patch` would mean a reader can see the files a task changed only when the task failed. Post each immediately after each writes its file, and only when that write succeeded: an artifact that was never written must not be announced as one that was. When no URL is configured the loop must do nothing at all and print nothing, which is the required behaviour and not a degraded mode. Failure of a push must be silent and total, bounded by a short timeout, and must never fail, stall or alter the run. The token must never appear in any output. Do not push the executor transcript in this task; T3 owns it. Do not add polling, controls or retention logic.
T2: bound the payload and make truncation impossible to miss, in scripts/ralph-log.sh. An artifact larger than a declared cap is sent truncated rather than dropped, because a large diff is exactly the one worth reading — but a truncated artifact must announce itself in a way a reader cannot overlook, so that a clipped diff can never be mistaken for the whole of what the executor changed. State the cap in one place and make it overridable by the environment variable `HARNESS_ARTIFACT_MAX_BYTES`, so an operator can raise it without editing the script; an unset or malformed value means the default, never zero, because a cap of zero would silently ship nothing at all. The announcement must be plain text a reader cannot miss, and must contain both the word `truncated` and the artifact's ORIGINAL size in bytes as a decimal number. The marker must survive the truncation: a note appended after the cap has already been reached is not a marker, it is more bytes that were cut. Include in the announcement how many bytes the artifact actually held, since "this was clipped" and "this was clipped at 4 MiB out of 41 MiB" are different facts and only the second one tells a reader whether to go looking for the original. Change no call site added in T1 and add no new kinds.
T3: push the executor's own transcript, in scripts/ralph-build.sh. The `.log` file holding the executor's stdout and stderr is written by the caller rather than by one of `ralph-log.sh`'s writer functions, so it needs its own push at the point the attempt's transcript is complete — after the executor returns and before the tree is reset. Use the helper from T1 with the kind `log`; do not add a second transport, a second identity or a second configuration path. It is subject to the same cap and the same truncation marker T2 established, and to the same silence: the transcript is the largest artifact a run produces and the one most likely to exceed any cap, so this is the case that proves T2 rather than a case that may skip it. Push it whether the attempt passed or failed — a failed attempt's transcript is the one a reader wants — and do not push a transcript that was never written. Change nothing about how the file itself is written; this task adds a push and nothing else.
T4: document the evidence channel in docs/ and in the header comment block of `scripts/ralph-log.sh`. There is no `--help` to extend — `run-loop.sh` carries only a usage string in a parameter default — and these scripts document themselves in the comment block at the top of the file, which is where a reader of `ralph-log.sh` will look for what it now sends. Say what leaves the worker and when — the prompt, the diff, the gate output, the metadata record and the executor transcript, each at the moment it is written rather than swept up afterwards — and state plainly why it is a push: nothing can connect into a worker, and a run that dies is exactly the run whose evidence matters most, so an artifact that has not already left is one nobody will ever read. Document the configuration as the same two variables the status channel uses, and say that with no URL set nothing is sent and nothing is printed. Document the cap, its override, and what a truncated artifact looks like to a reader. Record what this spec deliberately does NOT do: it does not store, index, retain or serve anything, and the coordinator that receives these artifacts and decides how long to keep them is a separate piece of work. Change no executable behaviour: this task adds documentation and comments only, and an unconfigured run must still be exactly the run it is today.
