T3: let a strategy declare the executable it needs, and preflight it, in scripts/run-loop.sh and scripts/loops/README.md. A conf may set STRATEGY_TOOLS to a space-separated list of executables; each is checked with command -v and an absent one stops the run before any work starts. This is the check that turns "strategy build-codex in an image with no codex binary" from a confusing mid-run shell error into a preflight failure that says what is missing. Join the EXISTING accumulation rather than adding a second preflight block: run-loop.sh already collects missing spec-declared Tools into one list and exits 3 with the message that the container needs attention rather than another retry, and a second block would produce a second message and a different exit code for the same class of fault. A missing spec tool and a missing strategy tool together must produce ONE message listing both and ONE exit 3. The message must name the missing executable AND the strategy that declared it, because "codex not found" without the strategy name sends the reader to the spec header, which is the wrong file. Fail closed: never a warning, never a continue. A conf that sets no STRATEGY_TOOLS behaves exactly as today. Document the key in scripts/loops/README.md's contract section as a declaration — it fits the existing "may only declare and export" rule and does not widen it — and record there the known duplication with the binding that OQ4 closes as accepted. Do not add STRATEGY_TOOLS to any existing conf in this task; the strategies that need it get it when their images exist.
