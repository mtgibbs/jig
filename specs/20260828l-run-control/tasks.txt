T1: skip a task whose own gate already passes, in scripts/ralph-build.sh. Add a predicate that takes a 1-based task index and answers whether that task's criteria already hold, then use it in the task loop immediately after `HB_TIDX` is incremented and before the attempt loop begins. The predicate answers false immediately when `$SPEC_DIR/tasks/` does not exist: with one gate for the whole spec the question has no sound answer, because a green gate there means the SPEC is done rather than that this task is, and skipping on that basis would mark every remaining task satisfied and report success having done nothing. It answers false when the task has no gate and false when the gate cannot be run — every uncertain case is fail-closed, meaning the task runs. Otherwise it runs THAT TASK'S gate only, never the cumulative group for tasks 1..n: the cumulative rule exists to catch a later task breaking an earlier one after work is done, and consulting it here would let a later task's failure stop an earlier finished task from being recognised. Bound the gate with `timeout` and treat a timeout as false, so a gate that hangs while being asked "is this already done?" cannot wedge a resume. When the answer is yes, announce it on stdout in the same shape as the other task lines, mark it in the heartbeat so a reader of the status file sees a task that completed rather than one that never ran, and continue to the next task WITHOUT invoking the executor and WITHOUT consuming an attempt. Announcing is not optional: work that silently does not happen is indistinguishable from work that silently failed, and a run whose output jumps from task 1 to task 4 with no explanation is unreadable. Do not touch the no-op guard that scores an attempt which changed nothing — it is a different mechanism for a different situation, and the reason this check goes BEFORE the executor is precisely so the two never have to be told apart. Write `return 0` or an explicit status at the end of the predicate rather than letting it inherit the exit status of its last construct, which for a loop or a conditional is reliably not what you meant.

T2: add the two overrides to scripts/ralph-build.sh — the mechanism a "retry from here" control needs. `RALPH_FORCE_FROM` holds a 1-based task index: task with that index and every task after it must run even when their gates already pass, while tasks before it may still be skipped. `RALPH_FORCE_ALL=1` disables skipping entirely, for a human who wants the work redone from scratch regardless of gate state. Neither variable set means the T2 behaviour is unchanged. Treat an unset or empty value as absent, and a value that is not a positive integer as absent rather than as zero — a malformed override that silently means "force everything" would surprise, and one that silently means "force nothing" would be worse. Announce at the start of the run when either override is in effect and what it will do, because an operator who set the variable in a previous shell needs to see that it is still acting. These are the only two knobs this task adds; do not add a polled control source, which needs a coordinator and belongs to its own spec.
