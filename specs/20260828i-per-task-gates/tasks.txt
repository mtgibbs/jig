T1: create specs/lib/assert.sh, the assertion vocabulary every gate in this repo will source. It is sourced, never executed, so it must not call `exit` at the top level and must not run anything on load. Define exactly two reporting functions: `ok` prints two spaces, `PASS`, two spaces and its argument to stdout; `no` prints two spaces, `FAIL`, two spaces and its argument to stderr and sets a variable `fail` to 1. Initialise `fail` to 0 at load. Define `gate_tmpdir`, which creates a temp directory into the variable `T`, writes a trivial executable script into it and runs it to prove the directory is not mounted noexec — if it cannot, print a single line naming the environment as the cause and exit 2, because a gate that cannot execute is neither a pass nor a fail and must not be reported as either. `gate_tmpdir` must also export `PYTHONDONTWRITEBYTECODE=1` and point `PYTHONPYCACHEPREFIX` inside `T`, so that running Python under a gate cannot leave a `__pycache__` in the tree the next scope check will measure. Define `gate_done`, which prints a `---` separator and then exits 0 printing `VERIFY: PASS` when `fail` is 0, or exits 1 printing `VERIFY: FAIL` otherwise. Do NOT define a `pend` function: a per-task gate asserts only its own task's criteria, so it has nothing to defer, and providing the verb is what invites the misfiled assertion this whole spec exists to remove. After this file is sourced, `pend` must not be callable. Do write a header comment naming the omission and its reason, so the absence reads as deliberate rather than forgotten — the ban is on defining the function, not on mentioning it in prose. Touch no other file; T2 owns the loop and T3 owns the self-test.

T2: teach scripts/ralph-build.sh to resolve gates per task, cumulatively, in scripts/ralph-build.sh only. Today `VERIFY="$SPEC_DIR/verify.sh"` is assigned once at line 58 and invoked at two places: after every attempt (`bash "$VERIFY"`, around line 196) and again at convergence under `STRICT=1` (around line 287). Add a function that, given the 1-based index of the task that has just run, prints the list of gate scripts to run for it. When the directory `$SPEC_DIR/tasks/` does not exist, that list is exactly `$SPEC_DIR/verify.sh` and behaviour must be bit-for-bit what it is today — this is a superset, and every existing spec in this repo relies on the old shape. When `$SPEC_DIR/tasks/` does exist, the list is the `verify.sh` inside each of the task directories for tasks 1 through N in `tasks.txt` order, and NOTHING for any task after N: running a later task's gate is the exact defect this spec removes. Match task directories by a two-digit, zero-padded index prefix, so the first task's directory begins `T01-`, the second `T02-`, and sort them numerically rather than lexically. If `tasks/` exists but a task listed in `tasks.txt` has no matching directory containing a `verify.sh`, print a message naming the missing gate and exit non-zero — do not skip it, because a task silently running with no criteria at all is strictly worse than the monolithic gate this replaces. Detect that up front, when the spec is first read and before any task runs, not lazily when the loop reaches the task: a missing gate discovered mid-loop gets folded into that attempt's verify feedback and retried three times, so the message never reaches the loop's own output and a human reading the run sees a model that could not satisfy a gate rather than a spec that is missing one. Invoke each resolved gate in the same manner and the same working directory as the single gate is invoked today, preserving the existing `STRICT` propagation, and treat the group as failed if any member fails while still running all of them so the executor sees every failure at once rather than only the first. At the convergence call site, additionally run `$SPEC_DIR/verify.sh` itself under `STRICT=1` after the task gates when `tasks/` exists — in the new shape that file holds only integration and end-state assertions and convergence is the sole place it runs. Change no gate file and create no spec directory; T4 owns the reference migration.

T3: create scripts/gate-selftest.sh, which proves a task gate can actually fail. It takes the path to a task directory (one holding `verify.sh` and a `mutants/` subdirectory) and must not modify the working tree it is pointed at: copy the repository to a temp directory and operate there, because a self-test that leaves a mutant behind would poison the very next scope check. Each file under `mutants/` is a complete replacement artifact whose first lines carry two comment fields: `MUTANT:` naming the assertion id it must break, and `WHY:` explaining the defect it introduces; parse both, and treat a mutant missing the `MUTANT:` field as an error rather than skipping it. Determine the path the mutant replaces from a third comment field `TARGET:` giving a repository-relative path. For each mutant in turn: install it at its target inside the temp copy, run the task's `verify.sh` there under a `timeout` so a mutant that makes the gate hang is reported as a hang rather than waiting forever, then require BOTH that the gate exited non-zero AND that the gate's output contains a FAIL line naming that mutant's declared assertion id. Those are two separate requirements and both must be enforced: a mutant that fails the gate for some other reason proves nothing about the assertion it claims to cover, and accepting it would leave exactly the unfalsifiable assertion this tool exists to detect. A mutant the gate accepts is a SURVIVOR and is the tool's headline failure — report it naming the mutant, its declared id and its `WHY` text. Then check coverage: collect every assertion id appearing in the gate's own `ok`/`no` calls, and fail naming any id that no mutant declares, since an assertion never observed to fail is in the same state as one that cannot. Finally, fail naming the file if the task's `verify.sh` contains the token `pend`. Exit zero only when every mutant was rejected for its declared reason, every id is covered, and no `pend` appears. Print a one-line summary of mutants killed versus survived. Do not wire this into scripts/ralph-build.sh: a mutant corpus that can block a running loop would become a new way to fail correct work, and this runs in CI and on demand only.
