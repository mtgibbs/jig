T3: add the applyable-patch writer to scripts/ralph-log.sh. Define `log_patch <task-label> <attempt>` writing `log_path "$1" "$2" patch`. Build it as `git -C "${ROOT:-.}" add -A -N -- . ':!.evidence'` followed by `git -C "${ROOT:-.}" diff -- . ':!.evidence'` — the intent-to-add pass is what makes NEW files appear in a diff at all, and without it a task whose deliverable is a new file produces an empty patch that `git apply --check` still accepts, which is a false green. Both commands must carry the `':!.evidence'` pathspec so the harness's own record never enters the patch. `-N` records intent only and must leave the real `git add -A` that follows it in the loop unaffected. Same LOG_OK guard, same `|| true`. No call site.

T4: add the per-attempt metadata writer to scripts/ralph-log.sh. Define `log_meta` writing `log_path <task> <attempt> json` as one JSON object with exactly the fields in spec.md section 3.2. Like every writer here it must exit 0 no matter what: guard on LOG_OK, wrap the write `|| true`, and never let an unwritable LOG_DIR return nonzero — the gate probes exactly that. No call site: do NOT touch ralph-build.sh or ralph-judge.sh in this task. T7 owns every call site, and adding one here both violates scope and invents a signature the gate does not use.
